# 🎬 Telegram Video Downloader Bot

بوت تيليجرام لتحميل الفيديوهات من يوتيوب وتويتر وفيسبوك وتيك توك وغيرهم (أي موقع يدعمه `yt-dlp`)، مبني على المعمارية الموصوفة في `VIDEO_BOT_DESIGN.md`:

- ✅ فصل الاستقبال عن الشغل التقيل — الـ handlers بترد فورًا والتحميل بيشتغل في الخلفية
- ✅ اختيار الجودة (أفضل جودة / 4K / 1440p / 1080p / 720p / 480p / 360p) بأزرار — بيخفي أي جودة مش متوفرة فعليًا للفيديو ده
- ✅ استخراج الصوت بـ 4 صيغ: MP3, M4A, WAV, FLAC
- ✅ معاينة (صورة مصغرة + عنوان + ناشر + مدة) قبل ما تختار الجودة، ونفس الصورة بترفق مع الفيديو النهائي
- ✅ تقسيم الملفات الكبيرة بـ ffmpeg لأجزاء **قابلة للتشغيل** (مش byte-split)
- ✅ تحميل بـ aria2c (اتصالات متوازية) لو متاح — بيرجع تلقائيًا لتحميل yt-dlp العادي لو مش متاح
- ✅ Webhook مؤمّن بـ `secret_token` + health check حقيقي (توكن + مساحة ديسك + CPU/RAM)
- ✅ رسالة تقدّم متحركة (HTML) لكل تحميل ورفع: شريط تقدّم + سبينر بيتحرك + السرعة + الحجم المنزّل/المتبقي + الوقت المتبقي، بتتحدّث كل ثانية
- ✅ أمر `/stats` يعرض حالة السيرفر كاملة: CPU/رام/ديسك بأشرطة نسبة، مدة تشغيل السيرفر، وضع التشغيل (Webhook/Polling)، وضع الرفع (Cloud/Local API)، وتفاصيل الطابور (تحميل/رفع/انتظار) لكل حالة
- ✅ من غير حد يومي أو حد لكل مستخدم — حد تزامن عالمي بس بيحمي السيرفر نفسه
- ✅ فحص مساحة الديسك قبل التحميل، وتنظيف الملفات المؤقتة في `finally`
- ✅ throttling لتعديل رسايل الحالة (كل ثانية)
- ✅ بلايليست: كل فيديو مستقل — فشل واحد مايوقفش الباقي
- ✅ أمر `/scan <لينك>` — بيفحص صفحة فيها لينكات لصفحات فيديوهات فرعية (زي صفحة قائمة فيديوهات)، بيجرّب كل لينك، وبيعرضلك قائمة تأكيد بأي فيديوهات فعلاً قابلة للتحميل قبل ما يبدأ يحمّلهم كلهم بأفضل جودة ورا بعض
- ✅ أمر `/pdf <لينك>` — بيحوّل أي صفحة ويب لملف PDF (Chromium headless، بيشغّل الجافاسكريبت زي متصفح حقيقي) ويبعتهولك كملف
- ✅ أمر `/speedtest` — بيقيس سرعة إنترنت السيرفر (تنزيل/رفع/ping) مباشرة من تيليجرام من غير ما تدخل السيرفر بالـ SSH
- ✅ أمر `/killall` — لصاحب البوت بس — إيقاف طارئ لكل التحميلات الشغالة ومسح كل الملفات المؤقتة على السيرفر دفعة واحدة
- ✅ أمر `/logs` — لصاحب البوت بس — بيبعتلك ملف اللوج بتاع البوت كامل كملف تكست
- ✅ أمر `/torrent <كلمة بحث>` وبحث inline (اكتب `@اسم_البوت` في أي محادثة) — مثال تعليمي يبحث في مصدر واحد ثابت وشرعي (نسخ Ubuntu ISO الرسمية)، وبيحمّل المحتوى الحقيقي فعليًا عبر BitTorrent (aria2c) ويرفعه على تيليجرام بنفس نظام الرفع والتقسيم والتقدّم المستخدم في باقي البوت
- ✅ ابعت ملف `.torrent` مباشرة كملف في تيليجرام وهيتحمّل ويترفع تلقائي — من غير بحث، انت بتحدد الملف بنفسك
- ✅ رسالة `/start` بتعرض كل الأوامر المتاحة
- ✅ زر إلغاء بيوقف فعليًا التحميل أو التقسيم الشغال (مش بس بيسيب الشغل يكمل في الخلفية) + حالة واضحة لكل طلب (قيد الانتظار/تحميل/رفع/تم/اتلغى/فشل)
- ✅ Graceful shutdown عند `SIGTERM` (إعادة نشر Render)
- ✅ 206 اختبار (unit + integration + smoke import) + CI على GitHub Actions

## 🚀 النشر على Render

1. **اعمل بوت جديد** من [@BotFather](https://t.me/BotFather) وخد التوكن.

2. **ارفع المشروع على GitHub:**
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/USERNAME/telegram-video-bot.git
   git push -u origin main
   ```

3. **على Render:**
   - New → **Blueprint** → اختار الريبو (فيه `render.yaml` جاهز)
   - أو: New → Web Service → Runtime: **Docker** → Health Check Path: `/health`
   - في Environment أضف: `TELEGRAM_BOT_TOKEN` = التوكن بتاعك

4. خلاص 🎉 — البوت بيستخدم `RENDER_EXTERNAL_URL` تلقائيًا ويسجّل الـ webhook بنفسه عند كل تشغيل.

> ⚠️ **الخطة المجانية في Render**: السيرفس بتنام بعد 15 دقيقة بدون طلبات — أول رسالة بعد النوم هتاخد ~50 ثانية عشان السيرفر يصحى. تيليجرام بتعيد إرسال الـ webhook تلقائيًا فمفيش رسايل بتضيع، بس فيه تأخير. الديسك في الخطة المجانية مؤقت ومحدود — مناسب للاستخدام الشخصي.

## 🚂 النشر على Railway

المشروع بيشتغل على Railway بنفس الـ `Dockerfile` من غير أي تعديل في الكود — الإعدادات بتتعرّف تلقائيًا:

1. **اعمل بوت جديد** من [@BotFather](https://t.me/BotFather) وخد التوكن (لو عندك واحد من قبل من Render، تقدر تستخدم نفسه).
2. Railway Dashboard → **New Project** → **Deploy from GitHub repo** → اختار الريبو (Railway بيكتشف الـ `Dockerfile` لوحده، مفيش حاجة زي `render.yaml` مطلوبة).
3. في تبويب **Variables** ضيف:
   - `TELEGRAM_BOT_TOKEN` = التوكن بتاعك
   - (اختياري) `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` لتفعيل Local Bot API Server (رفع لغاية 2GB)
   - (اختياري) `TELEGRAM_OWNER_ID` لتفعيل `/setcookies`
4. في **Settings** → **Networking** فعّل **Generate Domain** عشان ياخد دومين عام. البوت بيقرأ `RAILWAY_PUBLIC_DOMAIN` (بتتظبط تلقائيًا من Railway) ويبني منها رابط الـ webhook لوحده — مفيش حاجة إضافية تحطها.
5. لو عايز تحدد Health Check Path في الإعدادات، حطه `/health`.

خلاص 🎉 — نفس المميزات بالظبط (تحميل، رفع، `/scan`، `/stats`، إلخ) شغالة زي ما هي، غير الديسك اللي زي Render برضو مؤقت (Railway ماعندهاش Volume مجاني دائم إلا لو ضفت واحد بنفسك من Settings → Volumes).

### تفعيل رفع لغاية 2GB (Local Bot API Server)

بالـ Cloud Bot API العادي، أقصى حجم رفع هو **50 ميجا بس** — ده حد تفرضه تيليجرام نفسها ومفيش كود يقدر يتخطاه. عشان ترفع لغاية 2GB، لازم تشغّل سيرفر Bot API محلي بتاعك انت. `start.sh` و`Dockerfile` جاهزين لده أصلًا، محتاج بس:

1. روح [my.telegram.org](https://my.telegram.org) → سجّل دخول برقم تليفونك → **API development tools** → اعمل app جديد وهتاخد **api_id** و **api_hash**
2. في Render Dashboard → Environment، ضيف:
   - `TELEGRAM_API_ID` = الرقم اللي أخدته
   - `TELEGRAM_API_HASH` = الكود اللي أخدته
3. اعمل Deploy تاني — هتشوف في اللوج `Starting Local Bot API Server...` وبعدها `Local Bot API Server is up`.

لو الاتنين متسابين فاضيين، البوت بيشتغل عادي على الـ Cloud API العادي (50 ميجا).

**ملاحظة تقنية:** صورة `telegram-bot-api` الجاهزة مبنية على Alpine (musl-libc)، فالصورة الأساسية للمشروع بقت `python:3.12-alpine` (بدل `python:3.12-slim` المبني على Debian/glibc) عشان الاتنين يبقوا متوافقين. لو اتنسخ ملف alpine جوه صورة glibc بيفشل بالظبط برسالة `cannot execute: required file not found` — وده كان سبب المشكلة قبل كده. تجربة بناء `telegram-bot-api` من المصدر جوه الـ Dockerfile اتعملت وترفضت لأنها بتحتاج رام كبيرة وبتوقف/تعلق على أغلب خطط Render قبل ما تخلص.

**مهم:** تشغيل السيرفر ده جوه نفس الـ container بيحتاج رام وموارد أكتر من خطة Render المجانية (بتشغّل عمليتين مع بعض: البوت + سيرفر Bot API، وبيتعامل مع ملفات لغاية 2GB). لو هتستخدم الميزة دي بجدية، خطة مدفوعة (Starter على الأقل) هتكون أضمن.

### تسجيل دخول لمواقع/تغريدات محمية (كوكيز)

بعض المحتوى (تغريدات حساسة أو حساب خاص على X، مواقع بتطلب تسجيل دخول) مش بيظهر لـ yt-dlp غير لو معاه كوكيز جلسة تسجيل الدخول بتاعتك. الطريقة الآمنة الوحيدة اللي البوت بيدعمها هي إنك تصدّر الكوكيز بنفسك من متصفحك — البوت **مايعملش صفحة تسجيل دخول خاصة بيه** يسحب منها الجلسة، لأن ده نفس فكرة أي أداة تصيّد (phishing)، حتى لو النية كويسة.

الخطوة الأولى واحدة في الحالتين:
1. سجّل دخول في x.com (أو أي موقع محتاج كوكيز) في متصفحك العادي.
2. صدّر الكوكيز لملف `cookies.txt` بصيغة Netscape — أي إكستنشن "export cookies.txt" في متصفحك بيعمل كده.

بعد كده اختار طريقة:

**طريقة 1 — عن طريق البوت نفسه في تيليجرام (أسهل):**
1. جيب آيدي تيليجرام بتاعك (رقم، مش يوزرنيم) وحطه في `TELEGRAM_OWNER_ID` على Render.
2. اعمل Deploy، وبعدين ابعت `/setcookies` للبوت من حسابك انت بالذات.
3. ابعتله ملف `cookies.txt` (كملف)، أو الصق محتواه كرسالة نصية عادية.
4. البوت هيحفظه ويستخدمه من نفس اللحظة.

الأمر ده متعطّل تمامًا لأي حد تاني غير صاحب `TELEGRAM_OWNER_ID` — عشان أي حد غريب مايقدرش يستبدل جلسة تسجيل الدخول بتاعتك بجلسة تانية.

⚠️ الديسك في خطة Render المجانية مؤقت — لو السيرفر عمل ريستارت أو نام وصحي، الملف بيتمسح وهتحتاج تبعت `/setcookies` تاني.

**طريقة 2 — متغير بيئة (يعيش أطول، محتاج Deploy كل مرة تتغير فيها الكوكيز):**
1. افتح الملف بمحرر نصوص، انسخ محتواه بالكامل.
2. حطه في متغير بيئة `YTDLP_COOKIES_CONTENT` على Render (خليه `sync: false` — سري).
3. اعمل Deploy — البوت هيكتبه لملف على الديسك تلقائيًا أول ما يشتغل.

⚠️ ملف الكوكيز ده جلسة تسجيل دخول حقيقية لحسابك — متحطش محتواه في الكود ولا تعمله commit على GitHub أبدًا، وخليه في متغير البيئة السري أو تبعته مباشرة للبوت بس.

## 📦 حدود الرفع والتقسيم

| الوضع | أقصى حجم للجزء |
|---|---|
| Cloud Bot API (الافتراضي) | 49MB |
| Local Bot API Server (`TELEGRAM_BASE_URL`) | 2GB |

أي ملف ≤ 2GB بيترفع كملف واحد من غير أي تقسيم. أي ملف أكبر من 2GB بيتقسم تلقائيًا بـ `ffmpeg -c copy` (stream copy — سريع وبدون فقدان جودة) لأجزاء قريبة من 2GB لكل واحد، وكل جزء ملف كامل شغال لوحده، وبيتمسح من السيرفر فور رفعه. لو التقسيم هيطلع أكتر من 30 جزء البوت بيرفض ويقترح جودة أقل أو Local API Server.

**ملحوظة تقنية:** التقسيم بيستخدم الـ segment muxer بتاع ffmpeg، اللي بيقطع عند الـ keyframes — فكل جزء فيديو كامل شغال لوحده، والأجزاء **مش بتتداخل** وبتغطي الملف الأصلي مرة واحدة بالظبط (مجموع أحجامها ≈ حجم الأصل). حجم الجزء مش رقم ثابت بالبايت لأن القطع بيحصل بالزمن عند أقرب keyframe، عشان كده البوت **بيتحقق من كل جزء بعد التقسيم** ولو أي جزء طلع أكبر من الحد بيعيد التقسيم لأجزاء أصغر تلقائيًا. لو الملف مفيهوش keyframes كفاية عشان يتقسم (نادر)، البوت بيقولك كده بوضوح بدل ما يبعت جزء هيفشل رفعه.

```
├── main.py                  # نقطة الدخول: webhook (إنتاج) أو polling (محلي)

│   ├── validators.py        # فحص اللينكات (سريع، بدون شبكة)

│   ├── splitter.py          # تقسيم ffmpeg (segment-based، مش bytes)
│   ├── uploader.py          # الرفع مع retry ومسح فوري للأجزاء
│   ├── utils.py             # أدوات مساعدة (كلها مغطاة باختبارات)
│   └── handlers/            # Telegram handlers (Ingestion فقط)
├── tests/                   # 206 اختبار
├── start.sh                 # يشغّل Local Bot API Server (لو متظبط) قبل main.py
├── Dockerfile               # python:3.12-slim + ffmpeg + aria2 + telegram-bot-api
├── render.yaml              # Blueprint جاهز لـ Render
└── .github/workflows/ci.yml # lint → tests → smoke import
```
